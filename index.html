建築エネルギー × Agentic AI

BuildingAI

研究・分析プラットフォーム

異なる建物の BEMS データを、設備単位の理解・性能分析・根拠に基づく診断につなぐ Python アプリケーション。

PythonPyQt5FastAPISQLiteLLM / RAGYOLOv8
GitHub でソースを見る ↗
課題
建物やプロジェクトごとに BEMS の列名・言語・設備 ID が異なり、設備間の関係や分析に必要な信号を、そのままでは把握できません。
担当した開発
LLM による列の意味推定、設備 ID の正規化、温度信号の対応付け、設備分析を実装。PyQt5・API・データ管理を統合し、Agent の読み取り専用ツール呼び出し、根拠確認、回帰テストを開発しています。
技術実装
Python の解析サービスを、PyQt5 デスクトップ UI と FastAPI のタスク API に接続。SQLite でプロジェクト情報を管理し、LLM・RAG と決定的な工学計算を分離しています。
実装した機能・成果
BEMS の意味確認、設備別 COP・ΔT・エネルギーの可視化、ルール診断と根拠の追跡を一つのアプリに統合。博士研究の手法を、複数データで繰り返し分析できる実装へ展開しています。

確認しながら進める分析フロー

  1. データを取り込む
  2. 意味と設備を確認
  3. KPI・運転状態を分析
  4. 根拠から診断を検討

技術アーキテクチャ

  1. PyQt5 / FastAPIUI・API / タスクサービス
  2. Python意味解析・設備・KPI・診断
  3. Agent / RAGツール呼び出し・根拠確認
  4. SQLiteプロジェクト・履歴・データ
実装のポイント
  • 意味推定 → 人の確認 → 設備関連付け → KPI・ルール診断という一貫した分析フロー。
  • 読み取り専用の Agent がプロジェクトの根拠と検索した参考情報を分けて提示。BAS の制御操作は行いません。
  • 図面上の検出候補は、人の確認後に設備情報と関連付け。

継続ワークフロー × AI Agent

Executive HealthOps

研究・ポートフォリオ用プロトタイプ

健康資料、経時的な変化、管理目標、担当者・医師の判断を、一つの継続的なワークスペースでつなぐプロトタイプ。

PythonStreamlitFastAPISQLAlchemyAlembicAgent workflows
GitHub でソースを見る ↗
課題
分散した健康資料、重複・矛盾のある更新、人の判断と後続タスクの分断。
担当した開発
健康資料の構造化・確認・記録、履歴と出典を保持するデータモデル、確認待ちから再開する Agent ワークフロー、後続タスク編成と回帰検証を開発。
技術実装
Streamlit の役割別ワークスペース、FastAPI、SQLAlchemy・Alembic による永続化。Agent は管理されたツールとサービスを介して実行し、正式なリスクはルールで判定します。
実装した機能・成果
資料の確認・記録、状態の永続化、確認待ちからの再開と後続タスクを実装。合成データで回帰・ブラウザ検証を実施したプロトタイプ。
実装のポイント
  • 資料の原文根拠、単位の正規化、重複・矛盾、修正履歴を保持。新しい測定で過去の基準値を上書きしません。
  • 人や医師の確認待ちで停止し、結果を受け取って元の処理を再開。冪等性・実行制限・監査記録を備えます。
  • 正式なリスクは決定的なルールで判定。実運用の臨床サービスや臨床的有効性を主張するものではありません。

研究

研究概要

私の博士研究では、建築図面や BEMS の運転データから設備情報を理解し、空調設備の運用分析や省エネルギー改善につなげる手法を研究しています。YOLOv8 による図面認識、LLM によるデータ項目の意味理解、設備信号の関係復元、工学的指標に基づく診断を中心に取り組んでいます。

主な研究テーマ

建築図面の物体認識

手法
YOLOv8 で空調設備・窓等を検出し、転移学習の方法を比較。
目的
建築エネルギー解析に利用する図面情報の抽出。検出結果は予測として扱い、人が確認します。

BEMS データの意味理解

手法
LLM で多言語・異表記の項目を解釈し、設備 ID を正規化。設備・系統・流向を確認して供給・還りの温度を対応付け。
目的
同一設備の信号を整理して計算可能な関係を復元。根拠不足や曖昧な対応は計算を保留します。

空調設備の性能分析

手法
COP・ΔT 等の工学的指標とルールを用い、計測データと設備原理から運転状態を分析。
目的
異常の可能性を検討し、省エネルギー改善の確認事項を示すこと。改善効果や故障の確定は別途検証します。
